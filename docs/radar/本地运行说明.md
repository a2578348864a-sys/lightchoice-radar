# LightChoice Radar 本地运行说明（Windows）

这份说明只讲日常使用，不需要懂 Node、PostgreSQL 或 Worker。

## 日常只要记这些文件（都可以直接双击）

| 想做什么 | 双击这个文件 |
|---|---|
| 启动 Radar（只采集 + 阅读） | `start-radar.cmd` |
| 查看运行状态 | `status-radar.cmd` |
| 停止 Radar（数据库保留运行） | `stop-radar.cmd` |
| 全部停止（连数据库一起） | 命令行输入 `stop-radar.cmd all`（带参数，双击传不进去；平时双击 `stop-radar.cmd` 已够用） |
| **开启自动中文翻译**（需已授权持续付费） | `start-radar-translate.cmd` |
| **只停止自动中文翻译** | `stop-radar-translate.cmd` |
| 启动行业动态采集（第二主线） | 命令行 `node --env-file-if-exists=.env scripts/radar-ops.ts start industry` |
| 只停止行业采集 | 命令行 `node --env-file-if-exists=.env scripts/radar-ops.ts stop industry` |
| **启动市场信号自动调度（第四主线）** | 命令行 `node --env-file-if-exists=.env scripts/radar-ops.ts start market` |
| **只停止市场信号调度** | 命令行 `node --env-file-if-exists=.env scripts/radar-ops.ts stop market` |

启动后打开：

- 情报列表：<http://127.0.0.1:3000/all>
- 政策线索：<http://127.0.0.1:3000/leads>

**默认启动不会调用 DeepSeek**：`start-radar.cmd`（不带参数）只拉起数据库、API、网页和两个采集 Worker，自动翻译保持关闭。要开翻译，双击 `start-radar-translate.cmd`（与命令行的 `start-radar.cmd translate` 完全等价）；不带参数启动多少次都不会偷偷打开付费翻译。

> 浏览器控制台如出现 1 条 hydration（水合）警告：已知现象，根因是服务端按 `.env` 的 `SITE_URL=localhost` 输出规范链接、浏览器按 `127.0.0.1` 访问所致（R50 定位）。不影响任何功能；消除它需要改业务路由，超出当前授权，不要自行改代码。

## 启动时会做什么

`start-radar.cmd` 按顺序检查六件事，**已经在运行的就跳过，只补缺失的**：

1. 数据库（端口 5544）——没运行就启动，并等到真的能连接。
2. API（端口 3001）——没运行就启动，并等到接口返回正常。
3. 网页（端口 3000）——没运行就启动，并等到页面能打开（首次编译要几秒）。
4. AMZ123 线索 Worker——没运行就启动，并确认它拿到了实例锁（只消费它自己的两条私有队列）。
5. 公告/监管 Worker——没运行就启动，并确认它拿到了实例锁（只消费公告/费用/监管六条专属队列）。
6. **市场信号 Worker（第四主线）**——没运行就启动，确认拿到 PostgreSQL 顾问锁（`7204229008`），后台自主周期轮询获准来源。

三个 Worker 都是日常必要服务；**任何一个停止都不会影响另一个**，启动命令只会补起缺失的那个。**不会**自动启动 Ads、社区 RSS 通用采集器，也**不会**自动启用已停用的来源。

所以：

- 只有网页挂了 → 只补网页，API 不动。
- 只有 API 挂了 → 只补 API。
- 只有 AMZ123 Worker 挂了 → 只补 AMZ123 Worker，其余 Worker 不动。
- 只有公告/监管 Worker 挂了 → 只补公告/监管 Worker，其余 Worker 不动。
- 只有市场信号 Worker 挂了 → 只补市场信号 Worker，其余 Worker 不动。
- 数据库没起来 → 后面的服务不会启动，会直接告诉你原因。

窗口里的中文输出会写明每一步做了什么、是否就绪。

## 查看状态

`status-radar.cmd` 会显示：

- 数据库、API、网页、**AMZ123 Worker**、**公告/监管 Worker** 是否在运行（Worker 状态以实例锁为准）；
- 官方/监管五个来源的最近一次真实采集（状态、新增、时间、下次计划时间，逾期会标注）；
- 线索来源是否启用、每 360 分钟一轮；
- 上次成功采集时间、下次计划采集时间（计划时间不等于一定执行，Worker 没运行就不会执行）；
- 最近几次采集的结果；
- Ads 是否关闭；
- **自动中文翻译一栏**（见下）；
- 需要处理的问题（没有问题时显示「无」）。

### 自动中文翻译一栏怎么看

| 显示 | 含义 |
|---|---|
| 未启用（未运行） | 没有启动过自动翻译，也不会产生任何费用 |
| 运行中 | 翻译 Worker 正在跑，按周期处理新文章 |
| 运行中（预算已用完，不再发新请求） | 进程在，但本轮预算已用尽，不会发出新的付费请求 |
| 故障（上次未正常退出） | 上次翻译进程异常退出；采集不受影响，重新 `start-radar.cmd translate` 即可 |
| 预算已用完（未运行） | 本轮额度已用尽且当前没在运行；需要新额度必须由用户单独批准新预算窗口 |

同一栏还会给出：翻译 Worker 是否在跑（含 PID）、允许的来源（固定为官方/监管五来源）、启用基线时间、最后成功翻译时间、最近一次失败原因、当前预算（本轮已用/总额度 + 累计）、待处理文章数、最近一次执行的时间与处理篇数。

四个容易混淆的口径，页面已按此区分：

- **来源启用 ≠ Worker 正在运行**：启用只是配置，没人消费队列就不会采集。
- **health=ok ≠ 当前仍在自动采集**：它只代表上一次采集的结果。
- **next_fetch_at ≠ 到时一定采集成功**：它只是计划时间。
- **开关已设置 ≠ 翻译 Worker 正在运行**：状态读的是实例锁 + 心跳 + 数据库记录，不是环境变量。

## 停止

`stop-radar.cmd`：

1. **[1/7] 先停自动翻译 Worker**（付费的排在最前；正在进行的翻译会先收尾）；
2. **[2/7] 停公告/监管 Worker**，优雅收尾；
3. **[3/7] 停 AMZ123 Worker**；
4. **[4/7] 停行业动态 Worker**；
5. **[5/7] 停市场信号 Worker**（第四主线，释放顾问锁 `7204229008` 与调度控制状态）；
6. **[6/7] 停网页**（端口 3000）；
7. **[7/7] 停 API**（端口 3001，先核对进程属于本项目）；
8. **数据库保留运行**（若需要连数据库一起关，命令行执行 `stop-radar.cmd all`）。
- **只停翻译、不动采集**：双击 `stop-radar-translate.cmd`（等价于命令行 `stop-radar.cmd translate`）。两个采集 Worker、数据库、API、网页全部保持运行，已完成的译文保留。翻译本来就没在运行时，它会正常提示「未在运行」，不会动其他任何服务。

停止只会结束**确认属于本项目**的进程：先看端口是谁占的，再核对命令行。命令行对不上就拒绝结束，并打印占用者的信息。不会用「结束所有 node.exe」这种会误伤其他项目的做法。

## 关于长期运行（重要）

- 服务是作为独立进程启动的，不依赖启动窗口里的 Node 进程。
- 但**本工具不安装 Windows 服务、不创建计划任务、不设置开机自启**，所以**电脑重启后需要再双击一次 `start-radar.cmd`**。
- **开着自动翻译时**，电脑关机或 Worker 意外退出后，恢复方法同样是双击 `start-radar.cmd` 补齐五项服务、再双击 `start-radar-translate.cmd`——预算窗口存在数据库里，**重启不会重置已用次数与费用，也不会延长截止时间**；到期后即使重启，新的付费请求也会被拒绝（采集不受影响）。
- 「一键补起五个服务」**不等于** Windows 开机自动恢复，也**不等于**无人值守的进程监督——某个 Worker 之后再退出，仍需要再运行一次启动命令（或人工检查）来补起。
- PostgreSQL 必须由启动入口（`scripts/radar-local.ts`，独立隐藏控制台方式）拉起；**不要**用旧的 `postgres.exe` 直启 / `Start-Process` / detached 方式——那会复发「每条数据库连接弹一个黑色终端窗口」的故障。
- 是否能在关闭启动窗口后继续运行，取决于 Windows 会话本身；如果不放心，就保持启动窗口开着（窗口里的 `pause` 会一直停在那里）。
- 需要「开机自动启动」时，请单独确认后再配置系统级任务，本工具不代做。

## 出问题时看哪里

| 现象 | 先看 |
|---|---|
| 启动窗口说数据库没就绪 | `.data/_diag/postgres-5544.log` |
| API 起不来 | `.data/_diag/api-3001.log` |
| 网页起不来 | `.data/_diag/web-3000.log` |
| 线索 Worker 起不来 | `.data/_diag/worker-amz123-leads.log` |
| 公告/监管 Worker 起不来 | `.data/_diag/worker-announcements.log` |
| **自动翻译起不来 / 状态显示故障** | `.data/_diag/worker-translate.log` |
| 端口被别的程序占用 | 启动输出里有占用进程的 PID 和命令行；用 `netstat -ano | findstr :3000` 复核 |

日志只写运行信息，不包含 `.env`、数据库密码或代理凭据。

**电脑重启后**：双击 `start-radar.cmd` 即可恢复采集与阅读。如果之前开着自动翻译，再双击一次 `start-radar-translate.cmd`（本工具不设开机自启）。

**页面打不开但状态显示正常**：多半是 API 没起来（网页靠 API 取数）。`status-radar.cmd` 会把这种情况标成「本项目进程在，但探测不通过」，重新 `start-radar.cmd` 只会补起缺失的那个服务。

## 可选：自定义路径

如果 PostgreSQL 不在默认位置，可以在运行前设置环境变量：

- `RADAR_PG_BIN`：`postgres.exe` / `pg_isready.exe` / `psql.exe` 所在目录
- `RADAR_PG_DATA`：数据目录（含 `PG_VERSION` 的那个）
- `RADAR_PG_PORT`：默认 5544

默认值：

- `D:\Workspace\LightChoiceRadarRuntime\postgresql-17.11\pgsql\bin`
- `D:\Workspace\LightChoiceRadarRuntime\pg\data`

## 线索官方核实操作说明（R33–R35 起固定流程）

新 AMZ123 线索入库后，按以下固定流程做官方核实（不要临时写 SQL 或改 raw 对象）。工具：`scripts/record-lead-verification.ts`。

1. **读取线索**：`node --env-file-if-exists=.env scripts/record-lead-verification.ts show <线索id>` —— 查看当前核实状态与逐条主张。
2. **研究官方证据**（人工/Agent，有界只读）：拆分报道的具体主张 → 先查项目已收录官方来源 → 不足时查联邦公报 API（`federalregister.gov/api/v1/documents.json`）与公开官方页面；找不到就如实标「未经官方证实」，不猜测。
3. **编写核实记录 JSON**：`{ "expect": { "verifiedAt": "<show 看到的核实时间或 null>" }, "verification": { status, note, officialUrl, officialTitle, officialPublishedAt, effectiveDate, effectiveDateLabel, officialSource, verifiedAt, verifiedBy, claims: [ { claim, verdict: "supported"|"unverified", evidence, note } ] } }`。
   - `supported` 必须附官方原文引文（evidence），并写明证据边界（note）——例如"行政机关履职期限 ≠ 卖家整改截止日"、"规则修订方向 ≠ 已落地的具体金额"。
   - `unverified` 必须写明未证实原因（note）。
   - `effectiveDate` 只放官方文件自己声明的日期；用 `effectiveDateLabel` 写清它是什么（如"CBP Form 5106 信息核查加强执法开始日期"）。
   - `officialSource` 写证据机构（如"美国海关与边境保护局（CBP）与美国联邦公报"）——**证据机构是美国政府时不得写成 Amazon 官方确认**。
4. **预览**：`... preview <线索id> <记录.json>` —— 只校验和预览，不写库。
5. **应用**：`... apply <线索id> <记录.json>` —— 自动快照（旧记录 + 应用后状态）到 `.data/_diag/`，经并发保护（`expect.verifiedAt` 不匹配即拒绝，防止覆盖其他会话的新结果 + 数据库原子条件更新兜底）后写入并回读验证；重复应用相同内容会幂等跳过。
6. **回滚**：`... restore <线索id> <快照.json>` —— 仅当当前核实记录仍是该快照「应用后」的状态时才恢复旧记录；期间已有其他会话更新过（例如补充了新官方证据）会**拒绝恢复**并提示人工对比；重复回滚会明确报告「无需重复回滚」且不写入。只改动 `raw.lead.officialVerification` 一个字段；旧版快照（缺 applied 字段）会被拒绝自动恢复，转人工对比。

写入前强制校验：status 必须是四个既有枚举之一（matched-official / evidence-insufficient / third-party-only / access-restricted）；verification 必须是对象（双重 JSON 编码的字符串会被拒绝）；`matched-official` 必须有官方 URL/标题和至少一条 claim；`supported` 无官方原文依据会被拒绝；`unverified` 必须写明原因。页面（/leads/:id）会自动按主张逐条展示，无需改前端。核实记录是对官方原文的证据整理，不构成业务建议。

## 行业动态（第二主线，R53 起）

`http://127.0.0.1:3000/industry` 是独立入口：美国消费与电商行业动态，含五个主题筛选、每日精选、研究线索导出。与政策情报（第一主线）严格分开：行业条目不会出现在 `/all`。

- 来源六个（均已按许可分级）：BEA 经济分析局、美联储理事会（FRB）两个美国政府来源（公有领域，可存摘要可翻译可展示，默认 UA 直接可访问）；交通统计局（BTS）**已停用**——内容同为公有领域，但其 WAF 拦截自报爬虫 UA，伪装浏览器 UA 属规避拦截且无官方授权，停止自动采集（10 篇历史记录保留）；Retail Dive / Supply Chain Dive / Modern Retail（限制准入——出版条款未授权保存摘要或模型处理，**只存标题、链接、日期**，页内署名外链）。
- 行业中文处理有**独立预算窗口** `second-lane-20261025`：¥3 / 120 次硬上限，北京时间 **2026-11-01 03:06 到期**，与第一主线翻译预算互相独立、互不挪用。每轮最多 3 篇、每北京日最多 15 篇。剩余额度看 `status-radar.cmd` 或 `/api/site/industry/status`。列表按「完整中文情报在前、仅标题线索在后」分组展示，缺口如实标注。
- 到期或额度耗尽后：免费采集继续、已有中文保留、新条目只有规则分类不生成中文；不会自动续期。
- **停机补采边界（如实，不伪造完整性）**：BEA 的 RSS 自带约 48 条（覆盖约一年），停机数天可完整补回；三个媒体 RSS 每次只含最新约 10 条（按其发布节奏约覆盖 2–4 天），且未核实到可用的公开归档 feed（新闻 sitemap 同样只有 7–10 条）——**停机超过该窗口的快讯会留下真实缺口**，缺口体现为 `fetch_runs` 的时间空档，不会用旧数据冒充。恢复后补采到的历史条目按其真实发布日期入库，不冒充当天新闻。

## 市场信号（第四主线，AUTO-RUN 起）

`http://127.0.0.1:3000/market` 是第四主线入口（需管理员登录）：12 个市场信号模块的私有研究工作台（总览/搜索需求/商品与竞争/机会研究/预警/来源六页）。

- **本机自动情报流水线**：已废弃人工 CSV/Excel 文件导入路线。第四主线拥有专用后台调度 Worker（`apps/worker/src/radar-market.ts`），持有独立 PostgreSQL 顾问锁（键 `7204229008`），支持通过 `node scripts/radar-ops.ts start market` 脱离浏览器常驻后台自主轮询执行。
- **并发互斥与防风暴恢复**：调度器使用会话级排他锁（键 `7204229009`）防止多进程并发重复采集；关机停止，重新开机后多日停机最多补偿执行 1 个窗口，防请求风暴；失败自动触发 4 小时退避机制。
- **官方合规来源接入与风险隔离**：接入官方公开公共领域 CPSC 产品召回 RSS 2.0 数据流（免费 $0，无需 API Key），抽取消费品安全隐患并直通 M09 创新与安全反证及 M12 风险预警。严格分离安全反证与商业机会，绝不将召回误标为销量增长或暴利商机，类目推断 Browse Node ID 显式为 null。

## 中文政策解释与翻译状态（R39–R46 起）

**读者在文章页看到什么（R46 起固定顺序）**

1. 文章头部：来源简称 + 日期（发布/来源更新各自标注）+ 中文标题 + 「阅读原文」入口。
2. 重点速读：已取摘要的第一两句话，并注明它是什么（机器翻译未经人工核对 / 本站规则整理 / 英文原文未翻译）与覆盖程度（仅摘要 / 仅标题 / 已取得正文但来源只允许展示摘要）；拟议规则在此处挂「拟议规则，尚未生效」。
3. 关键信息：只有材料真实支撑时才出现。来源是解释里的结构化事实（keyFacts）：涉及商品、主要风险、官方做法、数量与金额、文件类型、发布机构——逐字提取、每项带「依据：命中词（字段）」；材料不支持就整块不渲染，不造占位行。
4. 详细内容：有正文且来源允许展示 → 中文译文优先；只有摘要 → 注明「不是完整正文」；没有中文 → 原文与原文链接。
5. 来源与核实说明（默认收起）：原文标题、来源与链接、日期口径、中文内容是什么、材料覆盖、内容修订、免责声明。

后端记录（材料状态、规则命中、程序检查、修订号、receipts）仍然完整保留，只是不再堆在阅读区。

## 历史队列积压（R50 盘点结论）

pg-boss 的 `pgboss.schedule` 里留着历史全量 Worker 注册的定时行。**只要有任何 Worker 在跑，pg-boss 的时钟就会每分钟为这些行创建作业**，而当前两个专用 Worker 都不消费它们，于是堆在 `created` 状态：

| 队列 | 何时被创建 | 现状 |
|---|---|---|
| `cron.sources.schedule` | 全量 Worker 采集调度 | 约 1 条/分钟，无人消费 |
| `cron.hot.rank` / `cron.content.sweep` | 每 5 分钟 | 无人消费（翻译 Worker 运行时才会消费 sweep） |
| `cron.ops.recover` | 每 10 分钟 | 无人消费 |
| `cron.hot.snapshot` / `cron.stories.links` | 每小时 | 无人消费 |

- **这些不是待采集文章**：`content.analyze`、`sources.fetch*` 的 `created` 数为 0，真实业务文章没有积压。
- **增长是有限的**：pg-boss 对未进入 active 的作业按 `start_after + 14 天`（`retention_seconds`）删除，维护扫描每个队列最多 24 小时一次，因此稳态约为 14 天的定时扇出（约 3 万行、pgboss 库约 20 MB 量级），不会无限增长。
- **本轮不做清理**：删除/取消历史作业需要单独授权，且误删会影响将来恢复全量 Worker。当前按已知限制保留，`status-radar.cmd` 不把它们算作待处理文章。
- 翻译 Worker 启动时会顺带把积压的 `cron.content.sweep` 作业按每 15 秒一个跑完（幂等，只写 `job_runs`），属噪音。
