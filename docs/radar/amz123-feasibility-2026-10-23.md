> 范围：仅 AMZ123 专项验证。未改动第一主线 V1 / V1.1 / V1.2 的既有收口状态，未新建数据库表，未注册常驻 Worker，未把任何 AMZ123 内容写入正式政策库。

## 结论先行

**建议：有条件接入——只作为「第三方线索发现入口」，不作为政策事实源。**

AMZ123 能在合规、免费、可持续的条件下，替 Radar 发现 Amazon 美国站那些**官方公开公告里没有**的政策变化。但它交付的是**线索**，不是**事实**：本轮 20 篇样本归并出 13 个政策事件，其中只有 **1 个**能用公开官方原文核实（另有 1 个官方有链接但不足以支撑全部主张），其余 6 个仅第三方报道、4 个官方正文被登录墙挡住、1 个根本不是平台政策。

**用一句话概括价值**：Radar 现在只能看到 Amazon 每月公开的 1–2 条公告（`sell.amazon.com/blog/announcements` 12 个月共 8 条），AMZ123 补的是这个缺口——它报道了卖家后台通知、卖家论坛、类别运营口径里的规则变化，而这些**恰恰是公开官方渠道查不到的部分**。因此它有补漏价值，但每条线索都要另做一次官方核实，核实成功率（本轮 2/13 ≈ 15%）决定了它只能是线索源。

## 二、合规核查（P0，先于采集）

**robots.txt（`https://www.amz123.com/robots.txt`，2026-10-23 实取）**
- `User-agent:*` 的 Disallow 覆盖 `/admin`、`/search`、`/search.htm`、`/api`、`/user-*`、`/thread-*`、`/tag-*`、`/cgi-bin`、`/prouser-*`、`/tools-*/search` 等。
- `User-agent:*` **显式 `Allow:/t`、`Allow:/b`**，并声明 `Sitemap: https://www.amz123.com/sitemap_index.xml`。
- 另对 GPTBot / Amazonbot / SemrushBot 等单独 `Disallow:/`。
- 结论：文章级路径（`/t/xxx`、`/kx/xxx`、`/b/xxx`、`/zb/YYYYMMDD`、`/report/xxx`）**未被 Disallow 覆盖**；站内搜索与 `/api` 被禁止，本轮未使用。
- 附带发现（重要工程结论）：`/search`、`/api`、`sellercentral.amazon.com/help/...` 均返回 **HTTP 200**。**HTTP 200 不能用来判断是否被授权**，采集器必须自己实现 robots 门禁（项目现有的「拒绝未批准非 RSS 来源」门禁正是必需项）。

**用户服务协议（`https://www.amz123.com/disclaimer`，2026-10-23 实取）**
- 第 10 条：用户在平台发表的原创内容著作权归用户本人，用户可授权第三方以任何方式使用。
- 第 10 条：第三方**出于非商业目的**转载到平台之外，应在正文开头显著位置注明作者姓名、给出原始链接、注明「发表于厦门品牌方舟科技有限公司」，且**不得修改演绎**；需修改或**用于商业目的**应联系用户取得单独授权。
- 第 10 条：平台提供的标识、版面、文本、图片等受著作权/商标权保护，未经权利人同意不得发布、使用、改写、再发行或用于商业目的。
- 第 8.4.2 条：平台不允许用户以任何手段收集、编辑、出售或无偿传播其他用户的数据。
- 第 6.1 条：平台不对所提供信息与技术/信息的绝对有效、准确、可靠作出任何承诺。

**授权判定（区分四件事，不含糊）**

| 事项 | 结论 |
|---|---|
| 用户可公开阅读 | 是 |
| 技术上可获取 | 是（文章页 SSR，无需浏览器/登录/验证码） |
| 网站规则允许自动访问 | **是**（robots 显式 Allow + sitemap；文章级路径未被禁） |
| 有权长期保存并再发布正文 | **授权未确认**（第 10 条自持权利条款与转载条款存在张力） |

据此确定的执行边界（本轮已遵守）：只落**标题、URL、作者、发布时间、摘要、标签、证据链接**等必要元数据；**不保存整站正文**、不复制正文入库、不改写正文、不作为商业用途再发布；引用时按协议署名作者 + 给原始链接 + 注明发表于厦门品牌方舟科技有限公司。站内私有接口 `api.amz123.com` 未调用、未逆向、未依赖。

## 三、样本与证据（20 篇报道 → 13 个政策事件）

样本取自 `sitemap_index2.xml`（14802 个 URL）与 `/t`、`/kx` 列表页，真实抓取并解析 SSR（Nuxt `__NUXT_DATA__` + JSON-LD）。20 篇报道、19 个作者、12 个不同日期，覆盖 2026-07-08 → 2026-10-21。完整字段（标题/原始 URL/可核日期/是否指向美国站/政策领域/是否有具体新规则/生效时间与依据/是否引用官方原文/报道性质/是否同一事件/官方核实状态/证据出处/权限与采集方式）见结构化样本文件。

**官方核实结果（官方语料 = `sell.amazon.com/blog` 全部 77 篇 + `sellingpartners.aboutamazon.com` 44 篇 + 联邦公报，共 321 页公开正文，逐条关键词检索）**

| 官方核实结论 | 事件数 | 事件 |
|---|---|---|
| 1 官方证据已核实 | **1** | EV-IOR（IOR 进口商资质收紧） |
| 2 有官方链接但证据不足以支持全部主张 | **1** | EV-AGED（FBA 超龄库存附加费 181 天） |
| 3 只找到第三方报道 | 6 | EV-TITLE / EV-ADS-PAY / EV-ADS-REVIEW / EV-CARRIER / EV-UL / EV-TOY |
| 4 内容并非政策变化 | 1 | EV-TRO（美国法院 TRO 维权案件） |
| 6 因访问限制无法核实 | 4 | EV-AWD / EV-PEAK-FEE / EV-AI-TAG / EV-VIDEO |

**两处真核实的证据链**
- **EV-IOR（结论码 1）**：AMZ123 报道称源头是 2026-06-03 签署的第 14411 号行政令《加强海关执法》，并称 2026-08-19 联邦公报公示。独立核对：Federal Register Notice **2026-16911**（2026-08-19，91 FR 53627）标题即 *Accuracy of Importer of Record Data Submitted to CBP*，摘要明写 "CBP is taking initial steps to implement Executive Order 14411 'Strengthening Customs Enforcement'"，正文涉及 CBP Form 5106 与 beneficial ownership / business structure；另有 FR Rule **2026-17354**（2026-08-25，91 FR 54800）引用 "Executive Order 14411, Strengthening Customs Enforcement, 91 FR 35125 (published June 10, 2026)"。**未**在已读公开文本中逐字核实的是「180 天 / 2026-11-30 修订截止」与「保证金 / 境内资产门槛」两项具体数值（位于行政令正文，公开接口未取到）。
- **EV-AGED（结论码 2）**：官方公开页 `sell.amazon.com/blog/ask/amazon-fba-beginners-guide-2026`（2026-03-31）明写 "an aged inventory charge. That's applied to items that are in our fulfillment centers for over 181 days" —— **181 天门槛已核实**；但各库龄段单价、15 日库存快照、2026-01-16 分层调价未在该页出现，也未在官方渠道检索到。

**关键反证**：47 篇样本的正文里，**站外链接只有 `mp.weixin.qq.com`（9 篇）**，官方链接数 **0**；站点自带的 `sources`（来源）字段 **47 篇全为空数组**。也就是说 AMZ123 自己不保留、不给出官方原文出处——**每条线索都必须另做一次独立的官方核实**，这是它不能当事实源的根本原因。

**与 Radar 现有覆盖的重合**：13 个事件**全部不在** Radar 现有覆盖内（`platform_policy` 3 条 / `ads_policy` 2 条 / `external_regulation` 20 条，均为开发库实测）。Radar 现有平台政策最新一条是 2026-05-22，且**没有 CBP/海关类来源**（只有 CPSC 召回 15 条 + 联邦公报 CPSC 3 条 + FTC 2 条）——这正是 EV-IOR 能成为真实缺口的原因。

## 四、去重：报道 ≠ 政策事件

- 20 篇报道归并为 **13 个政策事件**，**重复 7 篇**。多报道事件：AI 生成人物打标（3 篇）、AWD 大件停收（2 篇）、2026 旺季履约费（2 篇）、解压玩具下架（2 篇）、广告扣款改余额抵扣（2 篇）、TRO 案件（2 篇）。
- **标题完全相同**的去重条件会把 AI 标签、AWD、旺季费、玩具下架全部漏掉——这些事件标题、作者、日期都不同。
- 仅用关键词实体去重又会**误合并**：`广告` 把「季节性备货广告节奏」和「Alexa 广告商品占比」并成一组；`禁售/下架` 把「印尼 TikTok 下架」和「捏捏乐下架」并成一组。本轮实测已产生 2 例误合并，必须人工否决。
- 可用的指纹：**平台 + 站点/适用市场 + 政策主题 + 官方政策链接或编号 + 规则变化内容 + 生效日期 + 涉及商品/卖家范围**。落到实现上就是「政策主体 + 生效日期 + 官方政策链接/编号」三元组，任一缺失则标「待确定」，不强行合并。

## 五、自动化实验（合法入口，可重复）

**合法入口**：`robots.txt` → `sitemap_index.xml` → `sitemap_index1/2.xml` → `/t`、`/b` 允许路径下的文章页 SSR。**不依赖浏览器渲染即可取得文章级元数据**（列表页是客户端渲染，文章页不是）。

**可重复性实测**
- 发现层连续 3 轮：sitemapIndex=2、sitemap2=14802、listT=19、listKx=93，**三次结果完全一致**（逐项字符串相同）。
- 元数据层 12 篇文章跑 2 轮：正文内容哈希 + 发布时间 **12/12 完全一致**。
- 失败诊断：不存在路径 → 404 `not_found`；**robots 禁止的 `/search`、`/api` 与需登录的 Seller Central 帮助页同样返回 200** → 采集器必须自建 robots 门禁，不能靠状态码。

**能否稳定发现 / 能否正确筛选 / 能否排除营销 / 能否识别重复 / 能否找到官方链接 / 能否输出清晰核实状态 / 能否重复运行 / 单来源失败能否诊断** —— 逐项均已实测通过，详见结构化样本文件的 `automationExperiment` 段。

**未实现/未验证的部分（不冒充）**：本轮没有把 AMZ123 注册为常驻来源，没有建表，没有做长期运行观察，没有验证站点改版后的解析存活率；列表页分页未实现（改用 sitemap 归档覆盖）。

## 七、接入判断与最小方案

**不建议**把 AMZ123 接成常驻来源或事实来源；**建议**接成一个**低频、只读、只落元数据的线索发现入口**，按下面五步最小方案实施：

1. **发现**：以 `sitemap_index*.xml` + `/t` 列表页为入口，新增一个 `web_list` 类来源，**只落元数据**（标题/URL/作者/发布时间/摘要/标签），不落正文；沿用现有来源白名单与「拒绝未批准非 RSS 来源」门禁，不新增数据库表。
2. **筛选**：以 `Amazon + 美国站 + 政策领域关键词 + 生效时间抽取` 做确定性筛选，复用现有 `radar-rules`。
3. **归并**：用「政策主体 + 生效日期 + 官方政策链接/编号」组合指纹聚类，缺项标「待确定」。
4. **官方证据查找**：按 `sell.amazon.com/blog` 月度 sitemap → `sellingpartners.aboutamazon.com` 月度 sitemap → `advertising.amazon.com` sitemap → `federalregister.gov` 公开 API 的顺序检索；命中即生成官方证据链接，未命中标「官方正文不可核实」。
5. **事实链路**：第三方报道**只进线索层**，不写 `platform_policy` 正式来源；不改变三类统计口径，不新增人工录入或审核队列。

**持续运行成本**
- 依赖：**零新增依赖、零付费**。只需 HTTP 客户端 + JSON/XML 解析（项目已有）；仅当需要读客户端渲染的列表分页时才用浏览器（项目已有 Playwright）。不需要付费 API、付费模型、登录态。
- 请求量：稳态按每 6 小时一轮、单轮约 60 次请求（发现 4 + 样本 20–50 + 官方核实 3–4/事件）估算，约 **240 次/天**。
- 时延：发现层 < 3s；单篇元数据 0.4–1.5s；一轮约 40–90s。
- 维护：① AMZ123 是 Nuxt SPA，文章页 SSR 字段（JSON-LD / `__NUXT_DATA__`）改版即失效，需要版本探针；② 列表页客户端渲染，分页需浏览器或改用 sitemap 归档；③ 每月用 `sell.amazon.com/blog` 月度 sitemap 复核一次官方渠道变化；④ `author` / `tags` 属站点内部结构，改版会破坏解析。
- 额外成本：**0 元**（仅本地算力与磁盘）。

## 八、遗留风险与未验证项

- **官方正文不可核实是常态，不是例外**：4/13 事件的官方口径在 Seller Central（robots `Disallow: /` + 需登录）。本轮**未**尝试绕过、**未**自动登录、**未**抓取受保护内容；这类事件只能标「存在第三方线索，官方正文不可核实」。
- **「已核实」只覆盖已读公开文本**：`180 天 / 2026-11-30`、`保证金与境内资产门槛` 两项具体数值未逐字核实到，需要行政令正文（91 FR 35125）原文才能定论。
- **样本时间窗偏窄**：sitemap 的 `/t` 归档集中于 2026-07，本轮样本主要覆盖 2026-07-08 → 2026-10-21；更长窗口与季节性事件未覆盖。
- **单季结论**：只测了 3 个月窗口、1 个站点、1 种语言，未验证长期供给稳定性与改版存活率。
- **授权未确认项**：批量正文保存、正文再发布、商业用途转载、第三方内容「转载」条款与平台自持权利条款的张力，均需使用者本人向平台确认后才可扩大使用。
- **不改变既有结论**：本轮**未**改变第一主线 V1.2 的收口状态——公开供给上限来自 Amazon 自身（公告博客 12 个月 8 条），不是采集能力缺口；AMZ123 补的是「官方不公开但卖家需要知道」的部分，不改变官方供给的统计口径。
