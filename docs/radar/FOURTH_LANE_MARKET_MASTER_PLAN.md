## 1. 定位与总纲

### 1.1 第四主线在项目中的位置

前三条主线回答「平台规则是什么（一）」「行业大环境如何（二）」「消费者在说什么（三）」；第四主线回答「**具体市场上，需求、供给、竞争与价格正在发生什么可验证的变化，是否值得进入下一步研究**」。它以 **Amazon 美国站为核心市场**，把前三线的政策/行业/原声证据与商品级观测放到同一个研究链路里，最终产出**机会候选 + 商业情景 + 人工决定**，而不是自动选品结论。

四条主线顺序约束（README §2、AGENTS §3）在本计划中的体现：R0 已获授权执行；**R1 工程启动受 Gate B 约束**（见 §11.2），未获提前建设授权前不写业务代码。

### 1.2 两层能力结构

- **广域发现层**：榜单/类目/关键词的周期性扫描，发现「新面孔、突变、缺口」，输出候选线索（进入研究队列），不追求全量。
- **重点市场深度追踪层**：对人工选定（或研究优先级选中）的有限市场集合做持续观测（商品、价格、排名、竞争、外部平台交叉），维护可比较历史。

两层共用同一套来源、对象、证据、权限、时间序列与费用机制；区别仅在覆盖范围与观测密度。

### 1.3 不做什么（边界继承与强化）

继承 README §1 全部禁止项（不做全站爬虫、不做销量预测、不绕平台限制、关键词命中≠市场结论），并补充：

- **不做无来源的"市场估算"**：任何指标必须可追溯到具体来源事实（§4/§5）。
- **不做自动选品/自动下单**：机会评分只表示研究优先级（§7.3）。
- **不用模拟数据填充 12 模块**：缺数据的模块保留为「已设计、受阻、不可用」状态（§8.13）。
- **不因模型授权而外发未获许可的第三方数据**（§9.1）。

## 3. 时间语义与身份规则

### 3.1 五类时间戳（所有观测必须区分记录）

| 时间戳 | 含义 | 时区/精度 |
|---|---|---|
| `sourcePeriodStart/End` | 原始统计周期（榜单更新周期、ABA 周期、Trends 日/周窗口） | UTC 存储，展示按北京时区；精度=源声明（日/周/月） |
| `sourcePublishedAt` | 来源发布/榜单生成时间 | 同上；缺失留空不猜 |
| `sourceUpdatedAt` | 来源页面/数据集最后更新时间（**绝不冒充发布时间**，继承一线 `Updated on` 规则） | 同上 |
| `observedAt` | 系统观察（抓取/导入）时间 | UTC 秒级 |
| `ingestedAt` / `analyzedAt` | 入库时间 / 指标计算时间 | UTC 秒级 |

### 3.2 商品身份

- 主键概念：`marketplace=US` + ASIN；父 ASIN 与子 ASIN 分别建档并显式关联；型号/变体属性来自源字段，**缺失不推断**。
- 首次观察四分（全部分别记录，禁止合并）：`firstObservedAt`（系统首次观测）、`firstChartedAt`（首次上榜）、`pageLaunchClaim`（页面标注的上架时间，标注为"来源声明"）、`evidenceBackedLaunch`（有证据的新发布，如 SP-API `launch_date` 类字段）。
- 跨平台匹配（§8 模块 08）：eBay/Etsy/Walmart 条目与 Amazon 商品的相似性是**候选匹配引用**（带方法与置信标注），**相似品永不自动合并为同款**；人工确认前不参与同款比较计算。
- **身份修订传播**：ASIN 归属/父子关系/合并修正属于事实修订——使受影响商品的历史观测重新挂接、相关指标/机会进入待复核（复用 VOC revision + REVIEW_REQUIRED 先例）。

### 3.3 事实类型（五类，所有数据必标其一）

`official`（官方观测：Amazon 官方页面/API、政府数据）> `secondary`（二次展示：AMZ123 转载的工具数据——**保留原始生产者身份，转载不构成独立证据**）> `third-party-estimate`（第三方估算：Keepa/SellerSprite 类）> `derived`（系统计算：§6 指标）> `ai-hypothesis`（模型假设：§7）。

## 4. 历史与修订规则

1. **新快照不抹历史**：观测按 (对象, 指标, 周期) 追加；榜单快照保留整榜（含名次与入选集合）。
2. **事实更正**：来源发布更正（如 ABA 修订、价格回溯修正）→ 新事实版本 + 旧版本标记 superseded（不删除）；受影响 `derived` 指标重算，`ai-hypothesis` 与机会候选进入待复核。
3. **来源撤权**：沿用 VOC 批次撤销先例——撤销传播到该来源全部观测的用途层（停止展示/导出/模型外发），**已存的私有研究证据不删**（除非法律要求），相关指标标记「依据已撤权来源」。
4. **身份变化**：§3.2。
5. **派生失效链**：`Observation(版本 n) → Metric(输入版本 n) → Change → Opportunity/预警`。任一上游版本变化，链条下游全部失效或待复核，**绝不静默沿用旧结论**。

## 5. 指标可比性与计算规则（全局公式契约）

每个指标记录：比较条件、失败原因枚举、公式版本号、输入事实版本、证据来源。以下规则为 v1 冻结内容：

| # | 规则 |
|---|---|
| C1 | 搜索排名前进位数 = 上期排名 − 本期排名（正=前进）。**不得**换算成"需求增长百分比"。 |
| C2 | 价格变化率 =（本期价 − 上期价）/上期价，**仅当**前后价格口径可比（同 marketplace/同卖家类型口径/同报价构成：币种+运费+优惠资格一致）且分母>0。任一条件不满足→`NOT_COMPARABLE`，不输出数值。 |
| C3 | 跨类目 BSR 不直接比较（绝对值与变化率都不可比）。**不阻断**同商品合法价格比较——可比性按指标逐项判断，一处不可比不否定其他。 |
| C4 | 首次观察四分法（§3.2），禁止混用。 |
| C5 | 缺失（`MISSING`：源应有而未返回字段）、观察失败（`OBS_FAILED`：抓取/解析失败）、退出观测范围（`OUT_OF_SCOPE`：本期榜单未入选）、真实零值（`ZERO`：源明确为零）四态分别记录。 |
| C6 | 未进入本期 Top N ≠ 退出市场；**未知排名不得填 N+1**，记 `OUT_OF_SCOPE(unknown>`N`)`。 |
| C7 | 完整且定义一致的 Top N 榜单（同市场、同榜单、同周期定义、本期抓取完整无分页缺口）才可做：榜内排名比较、进入/退出、样本品牌分布比较。 |
| C8 | 分页失败或覆盖变化 → 仅受影响的榜单结论降级为 `PARTIAL_COVERAGE`，其余满足条件的指标照常计算。 |
| C9 | 样本品牌分布 ≠ 全市场份额；BSR ≠ 销量。所有展示附此限定。 |
| C10 | Google Trends 不同归一化口径（不同时间窗/地区组合的 0-100 缩放）**不得直接拼接**；拼接需同查询口径或按官方说明的重叠校准，且标注方法。 |
| C11 | 不同平台/人群/统计口径的数据不得相加为"市场需求总量"；跨平台仅做方向性交叉验证（§8 模块 08）。 |
| C12 | 指标公式版本升级 → 全量受影响指标按新版本重算并双写版本号，不就地覆盖历史版本结论。 |

## 6. 来源台账与证据等级

### 6.1 证据等级定义（与工程验收/运行状态严格分离）

- **L1 文档存在**：官方文档或可靠依据证明数据产品/接口/页面存在（本轮核验=附链接+日期；未核验=标 `本轮未核验`）。
- **L2 资格明确**：当前用户/系统具备的访问资格与用途边界有证据（账户存在、条款已读、免费额度确认），或明确"不允许/未知"。
- **L3 实际验证**：获准条件下真实取得数据，确认字段/范围/业务价值。**L3 ≠ 持续采集许可 ≠ 模型外发许可 ≠ 公开展示许可**——三者逐用途独立判断。

### 6.4 Amazon US 商品级主路径判定（Gate B 关键输入）

- **主路径（首选）**：SP-API（Catalog Items + Pricing 类 + Product Type Definitions）——资格明确后商品级 C/D/E 全覆盖；**R0-FINAL 实核（2026-10-26）：L2 负面确认**（项目零集成、.env 无 SP-API/LWA 凭据键；缺口=用户注册开发者应用+卖家授权）。
- **可接受替代路径 A**：官方榜单页+商品页受管采集——**R0-FINAL 实核**：robots.txt 未禁止榜单路径，但默认 UA 实测 503 反爬；人工可浏览、无人值守自动化受阻（伪装 UA=规避，BTS 判例），正式采集需官方许可。
- **可接受替代路径 B**：AMZ123 数据（R0-FINAL 区分）——热搜词页提供**关键词级**ABA 转载数据（无 ASIN）→ 支持能力 A，**不构成商品级路径**；商品级需 AMZ123 导航下底层工具的合法导出（逐工具 L2，SellerSprite 类=付费未授权）。
- **不采用**：Keepa/SellerSprite 订阅（付费未授权）；Google Trends/新闻/宏观（辅助证据，**不能替代商品级事实**——冻结）。
- **结论（R0-FINAL 更新）**：商品级三路径仍未取得 L2 → **商品级主路径资格未成立**；关键词级（能力 A）已获 AMZ123 页面级实证但按冻结规则**不得冒充商品链路实证**。Gate B 条件 2 维持待授权状态（§11.2）。

## 7. 12 模块能力契约

### 模块 01 搜索需求雷达

- **业务问题**：美国站买家在搜什么、需求在升还是降、长尾里有什么未被满足。**用户操作**：按市场/时间窗查关键词排名历史与聚类，发现上升词/长尾簇，进入机会候选。
- **必需字段**：keyword(string)、marketplace(enum:US)、sourceId、periodType(day/week/month)、rank(int)、searchVolumeOrFamousRating(源原生指标，无则空)、clusterId(词组聚类)、isBrandTerm(bool)、deltaRank(derived，C1)。
- **来源**：ABA（L1）/ POE（L1）/ AMZ123 底层工具（L1，逐个 L2）/ Google Trends（L1，辅助）。**偏差**：ABA 只覆盖品牌卖家可见口径；Trends 是相对指数非搜索量（C10）；AMZ123 转载保留原生产者（§3.3 secondary）。
- **周期与覆盖**：ABA 周级/月级；Trends 日/周；最少可比较历史=连续 2 个同口径周期，推荐 4。
- **指标与限制**：排名前进位数（C1）；聚类仅按词形/共现（规则层），不做需求规模换算；品牌词单独标记不混入通用词结论。
- **依赖**：→10（缺口）、→12（预警）。
- **复用与新增**：复用——json_list/web_list 采集类型、来源准入四权评审（先例 `.data/_diag/r53/`）、时间序列骨架（§2）。新增——关键词对象、聚类规则、排名历史查询。
- **验收**：抽 N 词人工对源页核 rank/周期一致率 100%；deltaRank 可复算；缺周期标 MISSING 不内插。
- **状态**：**BLOCKED（L2 资格，主源 ABA/POE 无账号；替代路径未核）**。

### 模块 02 类目市场雷达

- **业务问题**：类目边界与层级是什么、商品归属是否变化、细分市场在哪。**用户操作**：浏览类目树、看类目下商品/品牌分布变化、追类目迁移。
— **必需字段**：categoryId(节点 ID)、path(层级链)、parentCategoryId、version(来源版本/快照日)、asin 归属、迁移事件(from/to/依据)。
- **来源**：SP-API Product Types/Browse 分类（L1 已核文档）/ 榜单类目路径（L1）/ POE（L1）。**偏差**：类目树随平台调整版本化，历史观测按当时版本解释。
- **周期**：类目树月度快照；归属随商品观测走。
- **指标与限制**：层级深度不限制展示；迁移=商品归属版本 diff，须有人工或源证据，不自动猜。
- **依赖**：→03/04/05（归属下游）。
- **复用与新增**：复用——版本快照先例（article_revisions 思想）。新增——类目对象与快照。
- **验收**：类目身份可回链官方路径；版本变化触发受影响指标复核（§4.5）。
- **状态**：**BLOCKED（同 01 的 SP-API/榜单 L2）**。

### 模块 03 商品与新品雷达

- **业务问题**：这个市场里有哪些真实商品、新品何时出现、什么证据。**用户操作**：按类目/词查商品卡（父子/变体/属性/首次观察四分），标新品候选。

- **来源**：SP-API Catalog（L1 本轮已核：含属性/关系/排名）主；榜单/商品页（L1）替代；外部平台（模块 08）交叉。

- **指标与限制**：首次观察四分法（C4）；"新品"结论必须有四分中至少一种显式依据；无任何观测属性的商品**不建卡**（能力 C 判据）。
- **依赖**：←01/02 发现入口；→04/06/05 观测下游。
- **复用与新增**：复用——身份/幂等/修订机制全套（identity_key 先例）。新增——商品对象、四分字段。
- **验收**：抽样商品卡对源可核属性一致率 100%；身份修订传播实测。
- **状态**：**BLOCKED（商品级主路径 L2，§6.4）**。

### 模块 04 销售热度雷达

- **业务问题**：谁在榜上、排名怎么动、进出榜与新面孔。**用户操作**：看榜单快照与历史、进出榜事件、连续上榜名单、异常突变。

- **复用与新增**：复用——快照+幂等。新增——榜单对象、完整性判定。
- **验收**：快照完整性标志与真实抓取状态一致；进出榜可复算。
- **状态**：**BLOCKED（榜单采集 L2）**。

### 模块 05 竞争格局雷达

- **业务问题**：观测样本里品牌/商品分布怎么变、同质化与差异在哪。**用户操作**：看样本品牌分布时序、新进入品牌、功能差异对照。
— **必需字段**：brandId、sampleScope(榜单/类目/关键词口径)、shareInSample(derived)、newEntrant/exitFlag、featureDiff(规则抽取+人工标注)。

- **指标与限制**：shareInSample=样本内计数比例，公式版本 v1；跨口径样本不相加（C11）。
- **依赖**：←03/04。
- **复用与新增**：复用——确定性规则先例（L1 分类/行业门禁）。新增——分布计算。

### 模块 06 价格与促销雷达

- **业务问题**：目标商品/变体价格怎么走、谁在卖、促销什么条件。**用户操作**：看单商品价格历史、多卖家报价对比、促销条件、价格区间。

- **指标与限制**：价格变化率（C2 全条件）；价格区间=观测期 min/max（标口径）；**不做"历史最低价"类全史宣称**（观测起点限制必须展示）。

- **状态**：**BLOCKED（商品级 L2）**。

### 模块 07 趋势与季节雷达

- **业务问题**：需求是否季节性、事件冲击多大、趋势持续吗。**用户操作**：看关键词/类目级趋势曲线、季节性标注、事件对齐。

### 模块 12 机会发现与预警

- **业务问题**：把多源研究聚成可行动的机会清单，并在条件变化时提醒。**用户操作**：收/忽略/复核机会，配置预警阈值与冷却，看变化提醒与复盘。

- **来源**：全模块衍生 + 人工。
- **周期**：随上游；预警按规则窗口。
- **指标与限制**：预警阈值/去重/冷却/失效（来源撤权或事实修订→关联预警撤回）/撤回留痕；**站内展示默认，外部推送渠道仅设计不默认开启**（冻结）。

- **复用与新增**：复用——人工决定保护、撤回传播先例。新增——预警规则对象。
- **验收**：修订→预警撤回链实测；去重与冷却实测。
- **状态**：**BLOCKED（上游），规则框架 R4 建**。

**12 模块状态总表**（数据与业务能力层，非设计层）：**9 个 BLOCKED**（01/02/03/04/05/06/08/10/12——商品级或来源 L2 资格缺口）；**3 个 PARTIAL**（07 趋势、09 创新、11 商业可行性——辅助证据或一二三线先例存在）；全部 12 个模块的**设计契约**在本文件冻结（Gate A 范围内 PASS）。

## 8. 跨主线协同与工作台线索输出

### 8.1 三层研究语言（全模块共用）

每个研究结论分三层呈现且**分字段存储**：①观察到的变化（事实层，derived）；②原因解释与**反面证据**（解释层，引用一~三线材料与外部证据）；③是否值得进入下一步研究（判断层，人工或机会评分）。「已确认原因 / 相关现象 / 待验证假设」三态强制区分——机会候选中字段独立，禁止把假设写成已确认。

### 8.2 跨主线引用规则

- 四线引用一线（费用/政策事实）、二线（宏观与行业）、三线（消费者原声）证据时：**沿用原材料的用途与访问权限**（例：三线 SE 材料 store/privateRead 但无 modelSend/export——四线只能在私有研究内引用阅读，不得将其外发给模型或公开导出）。
- 缺某条主线证据时明确留空并标注（如"无消费者原声证据"），**不为凑齐四线证据制造材料**。
- 引用保留来源事实版本；原线事实修订/撤权 → 四线引用处同步失效/待复核（§4.5 链跨线延伸）。

### 8.3 向轻选工作台输出研究线索（设计，不实施）

- **方向**：四线机会候选经人工确认后，可导出为研究线索（含证据引用、市场、初步商业情景）供工作台侧参考。
- **边界（冻结）**：只通过**导出/人工转交**方式；不写工作台数据库、不改其代码与产品决策、不自动同步；工作台（V5/V6、端口 3010）保持完全独立。
- **许可**：导出内容按证据链的逐用途许可过滤（含三线引用材料的 export 许可检查）。
- 实施属 R4 之后，且需用户对导出形态的确认。

## 10. 中文产品体验与云端目标

### 10.1 信息架构（复用现有 Web 架构，不为 12 模块各建页面）

## 12. 验收口径与证据规范

- 状态词汇强制：验收 `PASS/FAIL/PARTIAL/BLOCKED/NOT_RUN`；运行 `NOT_STARTED/RUNNING/OBSERVING/STOPPED`；来源证据 `L1/L2/L3 + NOT_VERIFIED`；三者**永不混用同一字段**。
- **分层验收（第四主线专用）**：①设计冻结 ②工程验收 ③正式启用 ④自然新增/修订 ⑤持续稳定。历史真实材料可验①②相关项，**不能替代④⑤**；无合格新事件→`NOT_RUN`（非失败）；部分验证→`PARTIAL`。无新增≠系统失败；不得伪造变化或无限等待。
- **样本选择规则**：每验收批冻结分母与抽样规则（先例：`.data/_diag/r58/`）；排除规则显式（如无属性商品不验 C）。
- **证据标记**：真实材料 / 回放 / 隔离输入 / 正式运行四类来源标签强制。
- **语义验收**：自动程序检查（JSON/引用 ID/数值一致）与**必要的人工原文核对**分别报告；JSON 合法或模型自评**不构成**语义准确证据（先例：一线 8 样本人工比对）。
- **必测场景**：权限撤销传播、事实更正重算、旧任务回写拒绝、派生结果失效、预算耗尽停止、并发互斥、恢复续跑（全部有一至三线先例可复用）。
- **浏览器验收环境四确认**：地址/端口/进程项目路径/构建版本一致（先例规范）；API/单测不替代关键流程。
- **分母保护**：验收分母不得看到结果后调整；需用户决定的预算/部署/观察条件给建议+待决项，不冒充已批准。
- **产品判据（冻结）**：12 模块任一必要能力缺真实数据 → 第四主线完整产品**不得判 PASS**；有限工程交付不暗示全部产品与持续运行目标完成。
